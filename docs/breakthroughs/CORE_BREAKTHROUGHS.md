## 第一部分：核心架构攻关与技术突破 (Architectural Deep-Dive)

### 1. 跨平台书源规则解析引擎与多范式匹配架构
- **背景与痛点**：
  移动端「阅读」(Legado 3.0) 经过社区多年发展，书源生态涵盖了 XPath、CSS Selector、JSONPath 以及复杂正则替换和多段级联规则。在移植至 Windows 原生 JVM 环境时，直接引用 Android 依赖不可行，必须建立一套纯净、高效且 100% 规则兼容的统一解析层。
- **技术突破**：
  - 构建了统一的 `RuleAnalyzer`，将 `sourceRegex`（正则）、`@json:`（JSONPath）、`@css:`（Jsoup 选择器）与纯文本切片逻辑收敛为统一的解析抽象管道。
  - 支持多重提取链式调用（`rule1&&rule2`、`rule1%%rule2`），自动识别书籍元数据中的加密或动态字段。
  - 实现书源导入格式的鲁棒性校验，支持本地 JSON 文件与远程 HTTP/HTTPS URL 一键解析，内置多书源批量反序列化与去重。

```
[原始 HTML / JSON 数据流]
          │
          ▼
┌──────────────────────────────────────────────┐
│        Legado 统一规则解析器 (RuleAnalyzer)    │
│  ├─ JSONPath 引擎 (FastJson2 / Jayway)        │
│  ├─ Jsoup CSS 选择器 / DOM 遍历器             │
│  ├─ 正则捕获组与跨平台替换过滤器              │
│  └─ Rhino JS 动态函数安全求值管道            │
└──────────────────────────────────────────────┘
          │
          ▼
[强类型实体: Book / BookSource / Chapter / Content]
```

### 2. Rhino JS 沙箱引擎桥接与动态脚本安全求值
- **背景与痛点**：
  高质量书源广泛使用内联 JavaScript（`<js>...</js>` 与 `@js:`）进行动态解密、Token 计算和文本重组。若引入重型 Headless 浏览器（如 CEF/Chromium），将导致打包体积激增 200MB+ 且内存占用翻倍；若完全忽略 JS 执行，则导致 60% 以上的书源无法正常阅读。
- **技术突破**：
  - 引入经过深度轻量化定制的 **Mozilla Rhino** 引擎，内存开销小于 4MB。
  - **沙箱隔离限制**：重写 Rhino `ClassShutter` 与上下文工厂，禁止任何反射访问（`java.lang.reflect`）、系统进程调用（`Runtime.getRuntime()`）与本地文件读写（`java.io.File`）。
  - **全局上下文注入**：向沙箱环境安全注入 `result`（待处理文本）、`baseUrl`、`cookie` 等阅读器标准上下文变量，实现与移动端 100% 行为对齐的动态函数求值。

### 3. 基于 Skia 原生渲染的跨屏排版与双页/瀑布流混合布局引擎
- **背景与痛点**：
  移动端阅读器通常仅支持单页坚屏滑动或简单翻页，直接拉伸至 2K/4K 宽屏显示器会导致行宽过长、文字稀疏、严重破坏阅读体验。
- **技术突破**：
  - **自适应多模式排版系统**：
    - **双页并排阅读 (Dual-Page View)**：智能测算视口宽高比，在宽度 $\ge 1200\text{px}$ 时无缝切分为左右两栏，完美呈现纸质书籍对开质感；
    - **单页居中文档流 (Single-Page Centered View)**：限制最大有效阅读宽度（$800\sim 1000\text{px}$），防止视觉疲劳；
    - **图片瀑布流排版 (Waterfall Comic View)**：专为漫画与图文插画书源研发，支持 Skia 原生平滑缩放与垂直连续滚动。
  - **精细化排版参数引擎**：支持动态调整字体族（思源宋体/黑体/系统字体）、字号（12-36pt）、行距（1.2x-2.5x）、段间距、页边距，并通过 `Paragraph` 缓存机制消除高刷显示器翻页重绘掉帧。

### 4. Windows 原生 Win32 SAPI 无依赖低延迟 TTS 引擎
- **背景与痛点**：
  移动端朗读依赖 Android 内置 TTS 框架，而在 Windows 上集成第三方语音合成库不仅需要联网依赖，还存在额外体积包与授权问题。
- **技术突破**：
  - 设计 **Win32 SAPI (Speech API)** 原生桥接层，通过 PowerShell `System.Speech.Synthesis.SpeechSynthesizer` 与 COM 接口无缝联动。
  - **零外置依赖**：直接调用 Windows 10/11 系统自带的「微软晓晓」、「微软康康」及各类语言本地声音。
  - **异步朗读状态机**：提供带状态感知的 `TtsEngine`（Play/Stop/Speed Rate 调节），支持长章节自动分段预热，无缝实现跨章节背景听书与任务栏控制。

### 5. 大容量本地 TXT / 流式 EPUB 双重解析与内存优化架构
- **背景与痛点**：
  用户常有导入超大本地网络小说 TXT（50MB~200MB+）或排版复杂的 EPUB 电子书的需求。若直接整书载入内存，极易导致 JVM 触发 OOM 异常或严重卡顿。
- **技术突破**：
  - **TXT 正则目录流式预探测**：采用智能字符集探测（UTF-8, GBK, GB2312, Big5, UTF-16LE），利用基于内存映射文件（NIO `FileChannel`）的轻量分块扫描器，在数毫秒内提取全书上千章节目录偏移索引（Byte Offsets），实现单章毫秒级即时寻址。
  - **EPUB 流式解包与样式清洗**：利用纯 Kotlin 实现轻量 EPUB 解压流，解析 `container.xml`、`content.opf`、`ncx` 目录结构，剔除冗余内联样式并重构为适合桌面端渲染的干净段落模型。

### 6. 安装包极致体积裁剪与 SQLite 原生精简工程 (瘦身至 30~40MB 区间)
- **背景与痛点**：
  初期构建生成的 Windows 安装包体积高达 **115MB**，对于本地专注型阅读工具而言过于庞大，用户对轻量化、便携式体验有着强烈的诉求（期望降至 30~40MB 左右）。
- **深度排查与根因分析**：
  1. `androidx.compose.material:material-icons-extended` 单一依赖膨胀达 **36.03MB**，而整个桌面应用实际仅使用了十余个图标；
  2. `sqlite-jdbc` 内置了 Linux、macOS、Android、FreeBSD 等 23 个非 Windows 平台的动态库，体积虚胖 **13.47MB**；
  3. Compose Desktop 默认全量打包 Jlink 运行时包含无用 Java 模块，占用 30MB+。
- **技术突破与瘦身成果**：
  - **全量原生矢量图标库 (`LegadoIcons.kt`)**：彻底剔除 `material-icons-extended` 与 `material-icons-core`，采用 Compose `ImageVector.Builder` 自绘全部图标，代码体积不到 20KB。
  - **Windows x64 专用 SQLite 驱动裁剪**：剥离全部非 Windows 原生 `.so`/`.dylib` 动态库，仅保留 `Windows/x86_64/sqlitejdbc.dll`，将 SQLite 驱动从 **13.47 MB 骤降至 0.75 MB (净减 12.7 MB)**。
  - **精确裁剪 Jlink JRE 运行时模块**：精准圈定应用程序实际调用的最小 Java 模块集（`java.base`, `java.desktop`, `java.sql`, `jdk.unsupported`, `jdk.crypto.ec`），并配合 Jlink `--strip-debug` 与 `zip-9` 深度压缩。
  - **瘦身数据对比**：

| 交付形态 | 初始全量体积 | 第一阶段优化 | **最新极限瘦身** | 总体积缩减率 |
| :--- | :--- | :--- | :--- | :--- |
| **🚀 极速免安装便携版 (ZIP)** | - | - | **35.93 MB** | **完美命中 30~40MB 黄金区间** |
| **独立可执行 Uber-JAR** | 91.15 MB | 50.97 MB | **38.05 MB** | **-58.3% (净减 53.1 MB)** |
| **便携解压包 (app 目录)** | 102.85 MB | 66.83 MB | **53.91 MB** | **-47.6% (净减 48.9 MB)** |
| **Windows EXE 安装包** | 114.9 MB | 76.2 MB | **62.18 MB** | **-45.9% (净减 52.7 MB)** |
| **Windows MSI 安装包** | 114.2 MB | 75.6 MB | **61.61 MB** | **-46.0% (净减 52.6 MB)** |
| **全内置 JRE 便携版 (ZIP)** | 113.6 MB | 75.1 MB | **67.19 MB** | **-40.9% (净减 46.4 MB)** |

### 7. 跨协议全网发现与分类榜单引擎 (`ExploreEngine`)
- **背景与痛点**：
  原版 Legado 中各大优质书源均自带丰富的「发现/榜单」机制（例如周榜、月榜、完结榜、玄幻/修真等分类）。传统移植往往只聚焦搜索而忽视发现，导致用户无法发现新书。此外，各书源的 `exploreUrl` 协议极其多样：有的为纯文本多行 `分类名称::URL`，有的为复杂嵌套 JSON 数组，且 URL 中包含 `{{page}}` 动态分页宏。
- **技术突破**：
  - 构建支持**双重语法自适应解析**的 `ExploreEngine`，自动嗅探并兼容文本与 JSON 格式；
  - 智能替换动态分页宏（`{{page}}`、`{{page+1}}`），并无缝回退处理相对 URL 与绝对路径；
  - 实现了 `ruleExplore` 与 `ruleSearch` 的双重平滑降级机制，支持单键将发现书籍一键直读或加入书架。

### 8. Windows 系统字体深度枚举与 Skia 动态排版载入技术 (`FontManager`)
- **背景与痛点**：
  长篇小说阅读对字体舒适度要求极高。多数跨平台桌面阅读器依赖固定内置打包字体，不仅体积冗余数十 MB，且无法调用用户 Windows 系统中已安装的高品质商业字体（如微软雅黑、方正、思源、霞鹜等）。
- **技术突破**：
  - 建立 Windows `C:\Windows\Fonts` 系统字体目录动态探测器，自动索引中易宋体、微软雅黑、黑体、楷体、华文系及思源系列；
  - 零 C++ 依赖直接桥接 Compose Desktop / Skia `Font(java.io.File)` 原生加载通道，动态构建高效 `FontFamily` 并设有多级内存缓存；
  - 提供外部自定义 `.ttf` / `.otf` 文件选择器，并在 SQLite 键值库中实现排版偏好的毫秒级加载与断点恢复。

### 9. 零重型外部依赖 5KB Win32 原生全局硬件多媒体热键控制 (`GlobalMediaHotkeyManager`)
- **背景与痛点**：
  很多用户使用 Legado 进行听书（TTS）时，习惯将窗口最小化或置于后台，同时在桌面进行其他办公或游戏。此时普通窗口快捷键全部失效，迫使用户频繁切回窗口控制暂停或切歌，严重割裂听书体验。若引入庞大的 JNA/JNI 桥接库，不仅会增加包体积，且有跨线程崩溃隐患。
- **技术突破**：
  - 研发仅 **5KB** 的极简 Win32 原生后台监听伴侣程序（`legado-hotkey.exe`），利用 Windows 内置底层 `GetAsyncKeyState` 实现 0% CPU 占用的全系统全局按键捕获；
  - 全面支持键盘与无线耳机硬件多媒体按键（`VK_MEDIA_PLAY_PAUSE`, `VK_MEDIA_NEXT`, `VK_MEDIA_PREV`）及通用组合键（`Ctrl+Alt+Space/Left/Right`）；
  - Java 端采用守护线程与命名标准管道双向通信，退出时由系统 Hook 自动回收，彻底杜绝孤儿进程与内存泄露。

### 10. 智能多维度加权搜索排序引擎 (`SearchRelevanceEngine`)
- **背景与痛点**：
  导入 Legado 复合书源合集后搜索经典小说（如《斗破苍穹》），由于此前仅粗暴按网络请求先后追加，列表大量被同名同人衍生作、伪造书名的低质量条目占据，正品书籍被埋没。
- **技术突破**：
  - 设计多层级启发式权重量化模型：
    - **书名完全精准匹配**：赋予最高基准分（`+100,000`）；
    - **标点剥离与归一化匹配**：自动剔除《》、特殊括号、空格后比对（`+90,000`）；
    - **前缀与包含匹配**：依字符契合度赋予阶梯分（`+40,000` / `+20,000`）；
    - **作者完全匹配加权**：搜索作者时代表作品优先前置（`+50,000`）；
    - **信息完整度奖励与空壳惩罚**：封面（`+1,500`）、有效简介（`+1,000`）、最新章节（`+1,000`），依长度递增，惩罚无实际正文的空壳假书。
  - 单书源 6 秒超时保护，并发异步流式加权回填，彻底解决搜索结果鱼龙混杂的顽疾。

### 11. Legado 3.0 复杂规则解析器深度重构与直接属性/降级链路全兼容 (`RuleAnalyzer`)
- **背景与痛点**：
  在大量真实书源中，规则写法极为灵活：
  1. 许多目录规则为直接属性 `href` 或 `text`，旧版解析器误将其当作 HTML 标签 `<href>` 导致全部命中失败、清空章节链接；
  2. 书源广泛使用 `table@tr@td@a||class.list@li@a` 语法，导致 Jsoup CSS 解析器直接崩溃抛错；
  3. 独立二级目录提取（`ruleBookInfo.tocUrl`）未与正文解耦，导致阅读器陷入“正在加载章节内容”的无限死锁。
- **技术突破**：
  - **直接属性自动识别**：构建 `DIRECT_ATTRS` 白名单（`href`, `text`, `textnodes`, `html`, `src`, `content`, `title`, `alt`, `value`），遇属性规则直接从 DOM 元素提取，不再发起标签选择；
  - **`||` 降级备选链路**：实现 `splitAlternativeRules`，按顺序尝试多个候选规则，直至成功提取有效数据；
  - **`@` 层级下钻与位置索引**：支持 `tag.a.-1` 逆向取尾、`0` 取首、`!0` 排除表头等高级语法；
  - **URL 自动规范化**：实现 `resolveUrl` 智能补全相对路径；
  - **死锁彻底终结**：网络请求与目录解析在所有分支保证 `isLoading = false` 闭环，并给出直观的换源与排查指导。

### 12. 安卓端经典三栏沉浸触控翻页模型与多维书源导入生态体系
- **背景与痛点**：
  桌面端此前书源只能手动复制粘贴 JSON 文本；阅读器只能靠键盘按键或滚轮滑动，缺乏移动端阅读时自然沉浸的单手点击翻页体验。
- **技术突破**：
  - **多维书源导入体系**：选项卡集成 **网络在线 URL 一键嗅探导入**、**本地文件选择器导入 (.json/.txt)** 与 **剪贴板/源码粘贴**，具备对 API 嵌套包装（`data`/`list`/`sources`）的自动拆包与损坏单项自愈容错能力。
  - **屏幕点击分区引擎**：对标安卓《阅读 3.0》，基于 Compose `pointerInput` 精准计算 X 轴相对坐标，左区翻上一页（平滑滚动 85% 视口；章首无缝切上一章）、中区唤起菜单、右区翻下一页（平滑滚动 85% 视口；章尾无缝切下一章），且完全不影响鼠标滚轮的自然无级滚动。
  - **自由定制控制台**：支持可视化三栏布局预览，用户可自由选择比例（25:50:25 / 33:34:33 / 20:60:20）与映射动作，配置毫秒级存入本地 SQLite。
  - **全屏沉浸模式**：支持 `F11` 快捷键与图标一键切换沉浸模式，隐去多余视窗，专注纯粹文字。

### 13. 高吞吐智能防封禁离线批量缓存引擎与自定义存储管理体系 (`BookCacheEngine`)
- **背景与痛点**：
  小说章节若依赖实时在线加载，容易受弱网、源站限流或网站挂掉影响；移动端广泛依赖全本/分批离线缓存；且大量章节缓存占用 C 盘空间过大，用户迫切需要自由迁移至非系统大容量盘符。
- **技术突破**：
  - **高吞吐并发与防封禁时延**：采用 Kotlin 协程与 `Semaphore(3)` 严格限制最大 3 线程并发，每个请求内置 100ms 动态防封时延与失败指数退避重试，兼顾极速下载与源站友好；
  - **多层级多粒度缓存**：支持后 50 章、后 100 章、至最新章节、全本书籍批量缓存，支持随时一键中止；
  - **零延迟秒开缓存层**：阅读器切章优先穿透本地磁盘缓存，存在即瞬间呈现正文，网络请求完全静默旁路；
  - **自定义存储目录与安全隔离**：配置持久化至 SQLite (`cache_custom_dir`)，集成系统原生文件夹选择器，支持自定义迁移；缓存目录具备非法字符过滤与 MD5 哈希隔离保护，失效时自动平滑回退至默认 `%APPDATA%`；
  - **存储统计与一键清理**：递归扫描缓存目录，智能格式化展示各书及全局占用体积，支持单书与全局一键安全清除。

### 14. 视口级字符宽度加权虚拟分页与仿真滑动翻页及五维精细排版引擎 (`TextPagingEngine`)
- **背景与痛点**：
  传统桌面阅读器多采用无级垂直滚动流，缺乏纸质书及电子书阅览器“页”的空间感与进度把控；且不同字号、窗口缩放、中英字符混排时容易造成行尾裁切和分页紊乱。
- **技术突破**：
  - **CJK 与 ASCII 视觉宽度自适应折行**：创新引入字符视觉宽度加权模型（中文字符/全角标点权重 1.0，英文字母/半角标点权重 0.55），解决中英文混排参差错落；
  - **视口级双向虚拟分页**：结合容器实时像素宽高、字体大小、行间距、段间距与首行缩进，精确计算每页容纳行数与字符分片，零卡顿完成整章虚拟分页；
  - **左右仿真横向平移动画**：借助 Compose `AnimatedContent` 左右平移推拉动画，模拟纸质书翻页与移动端推页质感；
  - **页脚进度指示器**：分页模式下实时渲染 `第 X / Y 页 · 本章共 Z 字`，到达第一页或最后一页时智能衔接上下章节；
  - **五维精细排版控制台**：字号 (12~36sp)、行间距 (1.2x~2.5x)、段间距 (0~32dp)、首行全角双字符缩进开关、页面边距 (16/32/64dp)，满足资深读者的极致排版苛求。
